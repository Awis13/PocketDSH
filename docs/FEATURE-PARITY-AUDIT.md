# DeepSeek Harness → Pocket DSH feature parity audit

**Date:** 2026-09-08 · **Native baseline:** `312c953` · **Live Harness:** `0.1.3-alpha.2`

**Status refresh:** this audit describes the DSH backend at its original baseline. The subsequently added Swift Native Harness has a separate capability set. Use [the current roadmap](ROADMAP.md) for all G01–G46 statuses and the DSH/native distinction. Do not interpret features listed as already present below as automatically available through the native host.

This is a discovery document, not an implementation commitment. The web app was opened and inspected in Chrome on the running local Harness server, then compared with the current Swift source. No prompts were submitted, permissions changed, providers edited, presets duplicated, or agents started. Opening **Session log** did start a local ZIP download; that private archive is not included here.

## Coverage and evidence

- **UI:** directly opened/observed in the live browser. This establishes the control and visible behavior, not every backend success path.
- **Conditional code:** confirmed in the installed web plugin implementation, but its active scenario was not created during this audit. It must not be presented as a fully exercised workflow.
- **Partial:** Pocket already supports some of the capability; the row describes the missing part.
- Native absence was checked against the complete current `PocketDSH` source and its RPC calls, not inferred from a screenshot.

Visited: landing/new-session composer; Settings → General, Models, empty custom-provider form, Plugins configuration/list/detail, Agent presets and composition viewer; sidebar View options; Add workspace; session action menu; command picker; permission picker; model/effort menu; `@` file/session suggestions; existing session Chat and Trajectory; context meter; system-prompt control; request details; Session log; Open in app menu; attachment picker (cancelled).

Limits: Add workspace produced no picker in this browser session. The attempted full-text search interaction hit a native clipboard timeout, so its search behavior is source-confirmed, not end-to-end verified. Active goals/plans, pending approval/questions, jobs, reminders and workflow panels were examined in installed code rather than manufacturing tasks to make them appear. Not every custom deployment plugin was opened: the Telegram settings entry was observed, not exercised. This is a broad surface inventory with these explicit gaps, not a claim that every button has been executed.

## Already present — do not rebuild

Native streaming chat, session selection and history paging; workspace selection for new tasks; model search/selection; queue submission and text queue display; current-draft steering via Send context menu; stop; approval Allow once / Reject and Full access escalation; basic single/multiple-choice and free-text questions; image input/output and fullscreen preview; voice recording/transcription; basic Markdown tables and diff preview; themes, custom theme JSON; chat/terminal switch; iPad/Mac split panes and keyboard focus; bottom-follow and jump-to-bottom.

Multiple independent panes are **not** a substitute for navigating Harness's parent/child agent tree. Conversely, Pocket's terminal mode, split-pane workflow and custom themes need not be replaced merely to resemble the web app.

## Recommended milestones

1. **Protocol visibility and daily controls:** unknown-event fallback, retry/token-limit cards, dynamic server command dispatch, effort and permission selection, context/usage readouts. This prevents silent loss before adding more specialized views.
2. **Session and context management:** rename/archive/fork, server-side search, `@` file/session references, preset selection, queue editing/removal/steering, subagent navigation.
3. **Agent workflow surfaces:** plan review, goals, jobs/reminders, workflow panels, richer question navigation. Implement typed server contracts, not commands disguised as ordinary chat prompts.
4. **Inspection and artifacts:** tool side panel, trajectory, compaction detail, turn navigator, produced files/export, richer Markdown/diff rendering and non-image attachments.
5. **Optional administration:** providers/catalog, preset authoring, plugin settings, external-app actions, localization and feedback.

Milestones are slices of the inventory; some P1 items can move earlier depending on the user's main workflow. Keep the iPhone layout compact while making inspectors and hierarchy practical on iPad/Mac. Do not re-enable the previously rejected auto-collapsing composer as part of process compaction.

## Compatibility work before feature work

The README's stated rc.1 contract is older than the running alpha.2 server. Current sessions render, but that alone does not validate the newer surfaces. Pin a tested server version and add recorded, anonymized fixtures for new event/projection shapes, interactions, queue races and subagent addresses. Preserve unfamiliar data with a bounded fallback, rather than silently dropping it. An installed package proves implementation is present; it does not prove a specific deployment has mounted every capability.

No public GitHub issues, commits or pushes were made for this audit. Private session text, server credentials and exported logs are deliberately absent from this document.
